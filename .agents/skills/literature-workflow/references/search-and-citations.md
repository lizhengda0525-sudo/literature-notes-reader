# 收件、检索与书目核对

## 本地优先
1. 从 10_inbox/ 或用户明确指定路径取得实际 PDF，检查首页、版本与正文是否匹配。
2. 通过 register 核对文件哈希、已有 DOI 和 Zotero key；保留固定编号与版本历史。
3. 原文不得覆盖。相同文件复用已有编号，同作品不同文件用 add-version。
4. 关联 questions.md 中已有的 RQ；方向不明确时不擅自重写研究问题。本地 Zotero 可用于检索、读取既有书目及关联 key；sync 只更新书目字段。

只有 DOI、链接或摘要时，不标记全文已读；在 10_inbox/links.md 或检索日志记录全文获取状态。
引用 key 与作者、年份、DOI 都必须来自实际材料或核对过的来源。用 PDF 首页校对题名/作者，区分预印本与正式版、同名不同文章和版本差异。
Zotero 不可用不会阻断已有本地 PDF 的阅读；将待同步字段记录下来。

## 外部检索
先读 workspace.json 的 source_list 指向的项目 sources.md，按已确认的渠道优先级与当前研究问题选定检索范围。名单只在该文件更新，其他文档引用，不复制或生成并行版本。名单外的经典方法、近邻工作、反例或引用追踪可按研究需要补查，并在 search_log.md 说明理由。

当用户要求找论文、查新、最新进展，或关键书目信息需要外部核对时，使用当前可用的检索工具，优先论文原文、出版方、官方仓库及 DOI 登记信息。
核对候选身份后再获取全文；不把搜索摘要当原文证据，不因浏览或引用量获取失败而阻断本地阅读。
核对期刊/会议、正式轨道、年份与录用状态；OpenReview 在审稿件、Workshop 和预印本不能仅凭入口被当作主会正式论文。记录来源渠道及与当前任务相关或不相关的理由。
不默认查询引用量或所有被引文献。普通单篇阅读无需自动扩展成系统综述。

网页快照、批量检索结果、格式转换与分析脚本统一使用 .tmp/<任务>/，先把结论与可追溯链接保存到检索日志再删除。待登记 PDF 放 10_inbox/；不能把尚未归档的唯一原文当作临时文件删除。不得在临时目录里保留唯一的研究成果。

## 留下可复查的检索记录
按项目 search_entry.md 模板在 00_project/search_log.md 记录日期、数据源、检索式、时间/类型范围、实际获取材料、保留/排除理由、内部论文编号及后续补查。
把本项目 Pxxxx 与投稿论文参考文献编号分开。
查新同时寻找最接近工作和反例，记录未覆盖范围；结论使用“本次检索范围内未找到”，不宣称普遍不存在。
只在确实执行过检索、核对或下载后记为完成，不制造检索日期或来源。
