# 专题比较与候选想法

## 专题
1. 从 RQ 与目录确定输入论文，再读取笔记和支撑关键比较的原文页。
2. 对齐任务、假设、输入输出、数据集、独立样本单位、划分、指标定义与单位，再比较方法和数字。不同协议的结果保留差异说明。
3. 使用 review new 创建 review.json 和 review.md；专题已存在时更新原文件，不重复建立目录。
4. 将输入论文登记在 paper_ids，正文直接解释比较结果。区分作者结论与跨论文综合判断。
5. 写清一致结论、分歧来源、研究空缺、补查与实验启发，完成内容后 review stamp。

普通专题采用叙述性比较。系统综述、范围综述或元分析在用户要求时才确定检索协议、筛选和适用评价方法。

## 候选想法
1. 先固定支持问题的观察和来源，再写解释。区分观察、假设、机制、预测与实验证据。
2. 描述最接近工作做到哪里、拟改变哪一步及可能有效的条件。新颖性保持待查证。
3. 给出合理的替代解释及能区分它们的预测；考虑混杂、共同原因、测量/预处理伪迹和偶然变化，不强制凑固定数量。
4. 记录实际查新范围、支持与反对证据。
5. 设计最小实验：数据、基线、控制变量、消融、主指标、误差/不确定性、成本与失败判据。不要凭空填写已完成结果。
6. 使用 idea new 创建档案并声明 paper_ids/review_ids。材料不足时保留候选草稿。
7. 分阶段使用 candidate、needs_search、needs_experiment、supported、paused、dropped。supported 需要实际支持结果，不能由机械校验自动推导。

## 更新依赖
正文、书目、PDF 版本或输入范围变化后，check/index 会提示专题和想法过时。
先回查输入、更新实际分析，再 stamp。想法依赖的专题过时时，先更新专题。
不通过只刷新快照消除提示；保留未解决的分歧、缺失信息和继续位置。
