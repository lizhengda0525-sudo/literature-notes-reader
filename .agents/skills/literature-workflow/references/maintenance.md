# 维护、交接与清理

## 日常收尾
- 实质修改后运行 check；修复本次问题，再 index 重建人工与机器目录。
- state.md 只记当前阶段、继续位置、待办与阻碍，避免复制目录统计或累积会话报告。
- 只查询信息时无需重写状态；连接失败或环境变化时再运行 doctor。

## 环境与技能
项目依赖与恢复步骤见项目 90_system/environment/README.md。使用已就绪的 .venv，避免重复下载。
主技能的实际路径由 90_system/workspace.json 的 primary_skill.path 指定。原生位置为 .agents/skills/literature-workflow/。
如果原生目录受限，将修订版保存在 90_system/skills/literature-workflow/，验证后再切换 primary_skill.path，由 AGENTS.md 显式加载。不要改用全局技能目录，也不把原生更新记为完成。
finish-setup.cmd 在有写权限的普通终端将已验证的修订版更新到原生位置，完成后移除备用副本。不同且不完整的目标必须保留并报错；不可静默覆盖未知内容。
技能只保留一个主入口和按任务加载的参考；详细规则只在相应参考中维护。清理未引用的重复说明，不删除方法来源和许可证。
修改后按相对路径排序，重算除 manifest.json 外全部文件的 SHA-256，更新 manifest.json；运行 skill_package_errors 验证文件清单、内容、相对链接与来源，再运行 doctor 检查实际加载路径。校验通过不代表科学内容正确。
技能变更随项目本地版本管理保存，不上传研究资料或另建全局技能。写入受限时保留已验证的本地文件，并明确说明未完成的步骤。
只有修改脚本时才运行相关行为测试，不为每次阅读重跑全部测试。

## 版本与备份
PDF 是不可覆盖的原文；新版本用 add-version，保留旧文件。激活新版本后重新检查笔记和相关专题，人工核对状态退回待核对。
保留 registrations.jsonl 的追加历史，不清空或复用 Pxxxx。
原文、证据图片和手工笔记随整个项目备份；文本版本管理不能替代被忽略 PDF 的备份。用户要求备份时再执行，不默认发送远端。

## 清理
- 项目只使用根目录 .tmp/ 存放中间文件；按任务建子目录，不在根目录、论文目录或 90_system/cache/ 另建临时缓存。工具的原子写入 .tmp 后缀文件仅在目标旁短暂存在，写入成功后立即替换；不将其当作任务目录。
- extract 的已知产物位于 .tmp/extract/Pxxxx/；使用完运行 lit.cmd clean Pxxxx，仅清理本篇提取文本与清单。发现未知文件或链接则保留并报告，不扩大删除范围。
- 安装构建和测试使用 .tmp/ 下的独立 TemporaryDirectory，成功或失败后清理；安装错误输出到终端。技能更新若回滚也失败，必须先保留恢复副本，恢复并确认后再删除，不能为清空临时目录丢失有效文件。
- 搜索快照、OCR、临时页面、一次性脚本和导出文件用 .tmp/<任务>/；先将结论、来源和继续位置写入既有正式档案，再删除本任务文件，空目录随后移除。不清理其他仍在进行的任务。
- 可清理：已完成任务的临时下载、安装构建、日志、失效提取缓存和有对应源码的字节码。
- 必须保留：原文与版本、笔记和用户区块、证据图片、元数据、编号历史、专题、想法、模板、有效依赖和许可证。
- 删除或迁移前解析并验证完整路径，确保目标在明确允许的范围内；不追随链接到项目外操作。
- 不按扩展名或“暂存”字样批量删除全部文件；原文与人工成果逐项识别。
- 用户明确要求清理时，删除确认无用的中间文件；不确定的个人资料保留。临时资源不回存为项目内长期归档，任务结束不新增无用报告文件。
